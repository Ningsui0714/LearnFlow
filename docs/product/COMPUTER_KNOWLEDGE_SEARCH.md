# 计算机知识搜索 · v0.4

## 一句话逻辑

搜索不是替 Tutor 回答，而是先为“讲清楚这个问题”找到互补证据：规范定边界，教材讲机制，论文讲新结论，社区与仓库补实践。

## 检索流程

```text
学生问题
→ 判断：讲解 / 对比 / 排错 / 实现 / 研究 / 最新变化
→ 生成主题、英文检索词和证据角度
→ 可信来源目录 + 联网适配器并行召回
→ 读取命中的权威 HTML 页面并抽取问题相关原文
→ URL 去重、来源分层、相关性重排和域名去垄断
→ 最多 8 条带原文片段的 Evidence Bundle
→ Tutor 综合讲解并就近引用
```

“什么是”默认寻找四种证据：准确定义、核心机制、最小例子、边界与常见误区。它们是一次回答的材料角度，不是固定讲义模板。

## 来源层级

1. **规范和官方文档**：RFC Editor、语言规范、Linux/Python/PostgreSQL/Kubernetes 等官方文档。
2. **开放教材与大学课程**：OSTEP、CS:APP、Princeton Algorithms、MIT 分布式系统、CMU 数据库课程、D2L 等。
3. **论文与出版物**：arXiv 等；优先用于研究问题和近期变化，不替代稳定概念的教材解释。
4. **社区实践**：Stack Overflow、Wikipedia；用于定义起点、实例、排错和误区，并与高层来源交叉核对。
5. **代码仓库**：GitHub；用于观察实现，不单独决定规范或概念定义。

可信来源目录位于 `server/computer-knowledge-search.ts`。目录只提供领域先验和可靠入口，不能假装已经读取某个具体章节。

## 搜索后端

- 默认尝试公共 Jina Search，获取可供模型使用的查询相关正文片段。
- 设置 `EXA_API_KEY` 时优先使用 Exa 的 highlights 检索。
- 未设置 Exa、但设置 `TAVILY_API_KEY` 时使用 Tavily 的相关内容片段。
- Wikipedia、Stack Exchange、GitHub 和 arXiv 按意图调用，并与主搜索后端并行。
- 任一后端超时或失败都只影响该来源；其他结果仍可进入重排。
- 对目录中命中的 HTTPS HTML 页面最多并行读取 3 个，限制响应体、超时和证据长度；PDF 暂时只保留可信入口与人工编写的章节摘要。

可选 Key 只从 `frontend/.env.local` 或启动环境读取，不返回浏览器。

## 安全与证据边界

- 搜索结果是**不可信数据**，不能改变 Tutor 的任务和安全边界。
- 只接受外部 HTTPS URL，不读取本机地址。
- 最终回答只能引用工具实际返回的精确 URL，不能猜链接。
- 社区与仓库结果不能覆盖规范、官方文档和教材。
- 搜索、讲解和查看资料均不构成掌握证据，不写五核。
- 每次工具卡公开检索意图、证据角度、各后端结果数、采用理由与片段。

## 当前限制

- 公共搜索后端可能限流或不可达，因此保留可信目录和其他适配器降级。
- 并非所有官方站点都提供全文搜索 API；目录入口不等于相关章节证据。
- 当前重排是可测试的确定性规则，还没有用学习者反馈训练排序模型。
- 引用约束由提示词和 URL 白名单共同控制，尚未自动验证“句子是否被引用片段完整支持”。

下一步优先增加引用蕴含检查与实际问答评测集，而不是继续无边界增加来源数量。
