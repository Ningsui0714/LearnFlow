# 工作流调试数据说明（星辰平台）

> 配套工作流：`workflows/current/对话问答工作流.yml`、`workflows/current/测评出题工作流.yml`
> 生成器：`tools/gen_workflows.py`（重新生成请运行该脚本）
> 调试数据目录：`workflows/current/debug-data-chat-quiz/`（对话）、`workflows/current/debug-data-quiz/`（出题）

## 一、导入平台前必须做的事（人工步骤，写不进 YAML）

1. **替换账号占位**：两个 YAML 里 `appId: 12a0a7e2`、`uid: '21880654528'` 是占位值，导入星辰平台后需在节点配置中改为**你自己的模型账号**（否则大模型/代码节点运行报账号错误）；
2. **知识库**：对话问答工作流不依赖平台知识库（`kb_text` 由后端本地检索传入），如需平台侧 RAG 可另行配置；
3. **发布拿 flow_id**：发布后得到 `flow_id`，回填到项目 `.env`：
   - `XINGCHEN_CHAT_FLOW_ID=<对话问答工作流 flow_id>`（不填会回退通用 `XINGCHEN_FLOW_ID`，注意别打错流）
   - `XINGCHEN_QUIZ_FLOW_ID=<测评出题工作流 flow_id>`
4. 环境变量 `XINGCHEN_MODE=remote` 时生效；保持 `mock` 则走本地（不影响）。

## 二、调试方法

平台"调试/运行"面板 → 粘贴**入参 JSON**（即各样例文件里的 `input` 字段内容）到输入变量 `AGENT_USER_INPUT` → 运行 → 对照 `expected_output` 检查。

### 对话问答工作流（AGENT_USER_INPUT 契约）

入参（JSON 字符串）：
```json
{
  "message": "缺考怎么排除",
  "student_id": "STU-DEMO-001",
  "kb_text": "本地知识库检索结果（后端传入，可能是空串）",
  "history_memory": [{"role": "user", "content": "上一轮提问"}, {"role": "assistant", "content": "上一轮回答"}]
}
```

出参（结束节点 result_json，后端 `_extract_result` 解析）：
```json
{"status": "ok", "message": "口语化回答（≤500字）", "ai_generated": true, "sources": [{"title": "依据条目", "locator": "来源"}]}
```

| 样例文件 | 场景 | 验收要点 |
|---|---|---|
| `01-clear-question.json` | 明确提问（知识库命中） | message 非空且含缺考处理步骤；sources 含"成绩统计与缺考" |
| `02-vague-question.json` | 模糊提问（工作流兜底） | message 礼貌反问/引导，不报错 |
| `03-kb-gap-question.json` | 知识库缺口（kb_text 为空） | **不得编造**，明确告知未覆盖并给追问方向 |
| `04-multi-turn-question.json` | 多轮追问（history_memory 携带上文） | 按"封装"语境回答 getter；不重复上轮 |

### 测评出题工作流（AGENT_USER_INPUT 契约）

入参（JSON 字符串）：
```json
{
  "goal": "competition",
  "student_id": "STU-DEMO-001",
  "weak_points": [{"knowledge_point_id": "KN_JAVA_ENCAPSULATION", "knowledge_point_name": "封装与访问控制", "error_count": 2}],
  "knowledge_list": [{"knowledge_point_id": "KN_JAVA_CLASS", "knowledge_point_name": "类的定义与对象创建"}, "..."]
}
```

出参（结束节点 result_json）：
```json
{"status": "ok", "goal": "competition", "questions": [{"question_id": "GEN-xxx", "knowledge_point_id": "KN_JAVA_XXX", "knowledge_point_name": "知识点名", "title": "题干", "options": {"a": "...", "b": "...", "c": "..."}, "answer": "b", "explanation": "解析", "difficulty": 1, "source": "星辰出题工作流（本地校验通过）"}], "dropped": 0}
```

| 样例文件 | 场景 | 验收要点 |
|---|---|---|
| `01-with-weak-points.json` | 带薄弱点 | 8 题；封装/继承各 ≥1 题（薄弱点优先） |
| `02-no-weak-points.json` | 无薄弱点 | 6 题覆盖目标知识点 |
| `03-invalid-questions.json` | 大模型输出含非法题 | dropped>0 且 questions 均为合法题 |

## 三、与后端 payload 的对应（接入方核对用）

- 对话：`backend/server.py` `chat()` remote 分支 → `invoke_chat_workflow({message, student_id, student_profile, kb_text, history_memory})` —— payload 会被序列化进 `AGENT_USER_INPUT`；
- 出题：`_generate_diagnosis_questions()` → `invoke_quiz_workflow({student_id, goal, weak_points})` —— `knowledge_list` 由后端 `goal_engine` 路径注入（工作流内也可按 goal 自建，建议后端补齐后一起调试）；
- 结束节点输出键必须命名为 `result_json`（或 `final_result_json`），后端 `_extract_result` 才能解析。
